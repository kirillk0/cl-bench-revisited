# Сохранность результатов и восстановление после сбоя

При финальной публикации инструмент сообщил, что не смог остановить зависшую команду селективно и уничтожил весь контейнер. Перед этим Chromium-проверка HTML завершилась с кодом 137; связь с нехваткой памяти правдоподобна, точная причина сбоя не доказана. Все model runs и основной анализ к тому моменту закончились.

Последний подтверждённый удалённый commit до сбоя: `98665481f96531953c4bfb414ab70dd9a3d3da74` (15:53:43 UTC). Финальный push не состоялся. Восстановлены этот commit и отдельно выгруженный **до сбоя** `cost_audit_bundle.zip`.

## Что сохранилось

- **45 полных валидных trace.json**, из них 43 основных и 2 diagnostics. SHA-256 каждого совпал с pre-crash source inventory в cost_summary.json. Ни один не пересоздан из пересказа.
- Полный агрегированный cost/token/timing audit всех 60 попыток; все **448 оригинальных shell-команд**, их SHA-256, исходные exit codes и timing. Архив аудита содержит ранее выполненную сверку 500 успешных model turns и native-history checks.
- Генератор, seed/config, gold/reference SQL и код стенда. Обе БД повторно сгенерированы с точными первоначальными хешами.
- Последняя версия run_study.py восстановлена из зафиксированных в разговоре правок и **совпала с pre-crash SHA** `5bb2e53a168d3e05e7e2f56d7acc39423ec8232182638034220886b6769cfd48`. Конфигурация также совпала: `d6d3bfd410e62cfcdf02f2e55f63bc8f64ffcfc0c57ea09bfb564674b03f995a`.

## Чего нет

Полных исходных traces нет для:

- `main-glm-stateless`: T2, T3;
- `diag-glm-t2-history-r2`, `diag-glm-t2-reset-r1`, `diag-glm-t2-reset-r2`: T2;
- `diag-luna-managed-lifecycle`: все 5;
- `diag-luna-managed-maintain`: все 5.

Также утрачены приватные native checkpoints, полный исходный per-call ledger и поздние файлы semantic-grader/подробных качественных аудитов, не успевшие попасть в GitHub. Расходы и результаты проверок ledger сохранены в предварительно выгруженном cost audit, но не выдаются за сам исходный ledger. Сохранившиеся summary.csv/json и strict grade.json — ранний срез, **не итоговая accuracy-таблица**.

Числа и наблюдения потерянных задач, процитированные в REPORT.md, были прочитаны и проверены до сбоя. Там, где они перенесены из консольного анализа в новую выписку, это отмечено. Не создавались фиктивные `trace.json`, `manifest.json` или model responses.

## Повторное исполнение только инструментов

Для пяти GLM-задач из списка повторены все **50** сохранённых shell-команд в новой изолированной среде, на восстановленных БД. **Новых model API calls нет.** Сохранены оригинальные команды/их хеши и явно новые tool outputs в `public_results/recovery_tool_replays/`. Все 50 exit codes совпали с исходными. Неверные 1150→1550 denominators для history и верные 1000→1000 для reset воспроизведены.

Это позволяет повторно проверить вычисления/ошибку join, но **не заменяет утраченные финальные ответы модели и opaque reasoning state**. Нельзя использовать новые timings этих SQL как исходную стоимость модели.

Полный машиночитаемый перечень: `public_results/recovery_inventory.json`; ожидаемые pre-crash hashes находятся также в `public_results/cost_summary.json → snapshot.source_inventory`.

## Практическая воспроизводимость

БД: `python bench/generate.py`; аудит данных: `python bench/audit.py`. Для новых model runs нужны внешние credentials, root/chroot/Linux/seccomp и зависимости. Перед созданием jail: `python -c 'import sandbox'`, затем `python build_jail.py`. Не ослабляйте изоляцию, если эта среда недоступна.

Старые приватные checkpoint replays теперь невозможны напрямую; новые прогоны будут новыми попытками. Старый ранний pilot-luna-* имеет отдельную причину invalidation (shared /tmp), не связанную с финальным сбоем хранения.
