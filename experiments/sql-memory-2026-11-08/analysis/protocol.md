# Synthetic SQLite memory study — preregistration protocol

**Статус:** спецификация до эксперимента, не утверждение о внешней регистрации. Модельных вызовов при подготовке нет. До первого evaluation-вызова зафиксировать этот файл, `analysis_plan.md` и run manifest в commit с timestamp; заполнить gate ниже. Любое последующее изменение — датированное amendment, не перезапись задним числом.

## Вопрос и ограничения интерпретации

Помогает ли перенос состояния между задачами точности и/или стоимости решения новых SQL-задач? Primary оценивает **эффект режима целиком**, а не чистый эффект содержания памяти. Успех задачи, чтение заметки или корреляция длины заметок с успехом не доказывают причинную роль памяти. Память эндогенна: содержание, объём информации, затраты на её создание и стратегия агента не уравнены. Различия ICL–Markdown нельзя приписать одному формату хранения.

Все необходимые факты и определения восстанавливаются из **доступной на текущем шаге БД**, включая каталог/metadata и требуемые исторические данные; память лишь потенциально экономит повторное исследование. Промпт задаёт вопрос и формат, но не сообщает скрытый ответ. Независимый автор задач проверяет это reference SQL и metadata. Новые synthetic seeds снижают риск запоминания конкретных ответов, но не доказывают отсутствие training contamination или знакомства с шаблоном.

## Дизайн

Три arms внутри каждой модели; одинаковые задания, snapshots БД, доступ к SQLite и task-local scratch:

| Arm | Между задачами | Внутри задачи |
|---|---|---|
| Stateless | Новый нативный session/thread; scratch и файлы удалены | Обычная многошаговая работа, история текущей задачи сохранена |
| ICL-full | Один нативный session/thread, вся история и поддерживаемое API reasoning-state сохранены | Без ручной суммаризации, stripping, pruning или compaction |
| Markdown | Новый session/thread; сохраняется только `../memory`, исходно пустой | Агент сам читает/пишет через generic bash; без автоматической вставки заметок в prompt |

Во всех arms единственный action interface — одинаковый **generic bash** с SQLite CLI/Python; нет custom SQL/memory/retrieval tools, автосуммаризатора, embeddings или скрытого помощника. Различается только короткая инструкция о доступном переносе состояния. В Markdown не навязывать полезные факты/структуру заметок. Заметки пишутся в пределах бюджета текущего задания до его final answer, без бесплатного post-task turn. ICL и stateless также могут пользоваться временными файлами; между заданиями они уничтожаются.

**Нативность:** Anthropic native Messages; OR native chat API с нетронутыми поддерживаемыми `reasoning_details`/tool-call IDs; Codex native Responses Lite items, не эмуляция текстовым chat. Сохранять доступные opaque/signed/encrypted блоки по контракту провайдера, не извлекать и не восстанавливать скрытый chain of thought. Настройки reasoning фиксированы внутри модели во всех arms. «Полностью сохранённое native reasoning» заявлять только для подтверждённой семантики API; если retention отсутствует/непроверяем или происходит compaction, strict ICL-full не подтверждён. Не подменять его незаметно text-only вариантом.

**Модели и общий бюджет исследования:** Anthropic `claude-haiku-5-5` ≈ $20; OpenRouter `z-ai/glm-5.3-flash` ≈ $5; Codex `gpt-6-luna` по подписке, долларовая цена неизвестна, **не $0**. Эти точные IDs подтверждены реальными native tool calls в preflight; тарифы записаны в provider_config.json. До запуска фиксируются точные IDs, provider routing/version, SDK, тарифы/дата, reasoning effort, sampling и поддерживаемые usage-поля; никакой автоматической замены модели. Сравнения прежде всего внутри модели, не leaderboard разных API.

## Задания и выборка

Фиксированный порядок: **W1 → W2 → T1 → T2 → T3**. W1/W2 — знакомство со схемой, единицами, метриками; T1 — тренд с конфаундингом состава групп; T2 — перенос подхода на новый инцидент, не повтор старого численного ответа; T3 — необъявленное изменение схемы/семантики с доступными в БД признаками и определениями. T3 без предупреждения в model-visible инструкциях. Drift одинаков для всех arms и не зависит от их поведения. Сложность/размер drift фиксирует автор до просмотра результатов.

**Exploratory case study (final plan before evaluations):** одна новая пятизадачная последовательность на модель и arm: 15 попыток/модель, 45 на трёх моделях, включая warmups. Это поиск репрезентативных механизмов, НЕ confirmatory accuracy benchmark. Сначала Luna как development pilot. Если задачи слишком лёгкие/невалидны, изменения фиксируются отдельной версией с сохранением всех старых результатов, затем одинаковая версия даётся всем сравниваемым arms. Адаптивно добавленный кейс не объявляется заранее выбранной выборкой. Новые seeds и дополнительные повторы — только адресно для неоднозначных расхождений, а не обязательные четыре последовательности. Порядок arms и фактическое время каждого вызова фиксируются; кэш может быть общим у провайдера, поэтому cost трактуется как observed run cost, не гарантированно cold-cache comparison.

Генератор — другой агент; этот протокол не требует конкретных таблиц. Контракт: snapshots+hashes, вопросы, независимый reference SQL, ожидаемые ответы/допуски и rubric, скрытые от solver; проверка recoverability и отсутствия gold-файлов в sandbox. Не отбирать primary seeds по результатам тестируемых моделей. Адаптивный поиск трудных примеров — отдельная development-выборка; после заморозки критериев нужен новый untouched test set. Если генератор имеет adaptive ветку, primary использует общую заранее фиксированную траекторию; adaptive policy оценивается отдельно.

## Ресурсы, изоляция и feedback

На задачу: 80 модельных ходов и 15 минут wall time — лишь защитные stop guards, не reward. Один shell invocation: 60 s wall / 45 s CPU, 600 MiB адресного пространства. Вывод — до 60 000 символов (явная отметка truncation), НЕ лимит 50 строк. SQL-запросы не штрафуются и их число не входит в оценку correctness. Anthropic/OpenRouter max output на один ответ 8192 токена (включая thinking); это не общий task budget. Если output-limit остановил ответ, кейс маркируется censored/protocol issue. При срабатывании любого guard не считать ошибку памяти доказанной: разрешён диагностический повтор с повышенным guard, явно отмеченный. API таймауты и неизвестные списания записываются отдельно без тихого retry. Денежный guard с резервом: остановить Anthropic до $19, OpenRouter до $4.5, пользовательские потолки $20/$5. Сохранять всю историю и проверять отсутствие harness compaction; не уравнивать количество reasoning-токенов между архитектурно разными моделями.

Изолированный sandbox на arm×sequence; БД read-only, snapshot меняет только harness. Нет сети, чужих заметок, eval logs, gold, shell history, глобальных AGENTS/CLAUDE memory, background processes или shared caches с содержанием предыдущих задач. Provider prompt cache разрешён с одинаковой политикой, это не дополнительный semantic memory. Harness хранит логи вне доступной агенту ФС.

Primary: **никакой evaluator feedback**, correct numeric answers, pass/fail или hints после W/T. Естественные SQL results/errors разрешены и одинаково доступны. Optional standardized-feedback experiment — отдельный заранее выделенный запуск: один и тот же текст/момент/лимит для всех arms; gold numeric feedback, если нужен, только в этой отдельно маркированной ветке. Не смешивать её с primary.

## Outcomes и causal diagnostics

Primary: средняя доля успешных T1–T3 на sequence, бинарный success по frozen rubric (необходимые численные поля с допусками + требуемая интерпретация/основание). Secondary: каждый target, partial score, SQL/schema errors, стоимость и время до final, использование устаревшей схемы. W1/W2 не входят в primary accuracy, но входят во все затраты подготовки.

Причинные вмешательства — отдельные forked target replays на том же DB hash и pre-target checkpoint: **удаление конкретной заметки + sham, reset history, transplant memory, повтор неизменённого candidate**. Allocation, controls, ограничения и расчёты в `analysis_plan.md`. Primary state после replay не меняется. Диагностика обнаруженного расхождения условна на selection, не оценка population effect памяти.

## Gate перед первым вызовом

- [ ] Freeze commit, manifest, seed/snapshots/reference SQL/rubric и независимые deterministic generator checks.
- [ ] Точные модели/тарифы, native reasoning retention, запрет auto-compaction и session isolation подтверждены доступной документацией/конфигурацией; неизвестное помечено, strict arm не переименован молча.
- [ ] Mock/replay проверки adapters без моделей: native blocks round-trip, новый thread действительно пуст, разрешён только bash, нет auto-read Markdown и hidden persistence.
- [ ] Worst-case budget/context fit; все limits и diagnostic queue зафиксированы. Глобальный денежный/подписочный cap не превышается.
- [ ] Сырые usage/timing logs и evaluator вне sandbox; результаты ещё не просмотрены. Все amendments опубликованы до evaluation.
